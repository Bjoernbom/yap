# CLAUDE.md

## Project

yap is a native macOS push-to-talk dictation and meeting-notes app. Everything
runs on-device. The product and technical plan is `docs/PLAN.md` — read it
before starting work; it is the source of truth for scope, stack and voice.

yap 1.0 is a from-scratch rewrite. The old Tauri app (0.4) lives only under the
`v0.4.0` git tag; do not port code from it.

## Stack

- Swift 6.2 (strict concurrency), SwiftUI + AppKit, macOS 26+, Apple Silicon only
- `YapKit` Swift package (root `Package.swift`): all logic, no UI
- App target generated by XcodeGen from `project.yml` (no committed `.xcodeproj`)
- Speech: FluidAudio (Parakeet TDT v3, VAD, diarization); LLM: Apple Foundation Models
- Storage: GRDB; notes are Markdown files. Updates: Sparkle 2

## Commands

```bash
swift build          # Build YapKit
swift test           # Run YapKit tests (Swift Testing)
make app             # xcodegen generate + Debug build of yap.app into build/
make run             # Build, quit any running yap, launch it
make clean           # Remove build/ and the generated yap.xcodeproj
```

The app target needs XcodeGen (`brew install xcodegen`). DEBUG builds have a
Debug submenu in the menu bar menu that drives the notch with fake levels; see
`App/Sources/Debug/OverlayDemo.swift` for the launch arguments.

## Layout

```
App/Sources/         The app: menu bar, notch overlay, windows (thin, UI only)
App/Resources/       Bundled resources (Pixelify Sans + its OFL license)
project.yml          XcodeGen spec for yap.xcodeproj
Sources/YapKit/      Core logic, grouped by folder: Input, Audio, Speech, Text,
                     Output, Dictation, Notes, Store
Tests/YapKitTests/   Swift Testing tests
spikes/<name>/       M0 throwaway experiments, each its own Swift package
docs/PLAN.md         The plan
docs/spikes/         Spike findings
design/              Brand assets
```

## Code style

- Tabs for indentation
- Swift API Design Guidelines naming; small types with one job
- `async`/`await` and actors over callbacks and locks; `Sendable` everywhere
- No force unwraps outside tests
- Comments explain why, not what

## Workflow

- One PR per logical unit, squash-merged into `main` after `swift build` and
  `swift test` pass locally.
- Heavy builds: this machine has 18 GB RAM. Don't run more than one large
  build per worktree at a time, and clean up `.build/` in worktrees you remove.
- Model files and audio fixtures larger than a few MB are never committed.
